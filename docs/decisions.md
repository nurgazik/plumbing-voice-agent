# Decisions

One entry per decision, dated, newest first, append only. Non-obvious calls only.

Entry shape from 2026-09-14 on: the situation, what we chose over what, what we accept by choosing it, and when to reconsider. Rejected routes and research that led nowhere go here too, with the constraint that killed them, so a contextual no is not read later as a universal no. Earlier entries keep their original one-line form.

- 2026-09-14 First real call through the whole step 2 path, no replay: opener, triage, name, address, photo asked with a reason, get_photo_analysis called after "I texted", the ambiguous sink photo described honestly with a follow-up question, callback number confirmed without digits, routine callback line, STOP line. n8n answered the tool in 1.3 s; the photo row was stamped with the Retell call id. Retell cost 27.4 cents for 2m15s (voice engine 12.4, TTS 3.4, Haiku 5.6, an "llm_token_surcharge" 4.5 and a "gpt_4_1_text_testing" 1.5 that Retell's docs do not explain; inferred: large-prompt surcharge and post-call analysis). Average prompt 7.2k tokens per turn because the whole rules file rides on every turn; that is the cost lever if it matters.
- 2026-09-14 The Twilio number connects to Retell through a Twilio Elastic SIP trunk (Retell's documented method for an existing number), imported into Retell with credential auth and bound to the agent for inbound. Chosen over a Retell-bought number ($2/month, and a second number, so the caller would text one number and talk to another, which breaks the photo loop). Retell charges nothing per minute for SIP-imported telephony and no number fee; the call costs voice engine $0.055 plus Haiku $0.025 per minute; Twilio keeps its $1.29/month and its own SIP per-minute rate (not verified). Accepted: a SIP password in `.env`. Unverified until tried: that the number keeps receiving MMS with its voice side on a trunk; Twilio's number record holds messaging routing separately from `trunk_sid`, so it should. The sequence lives in `agent/connect-number.sh` because Claude's sandbox refused to run it as a production change; Ray runs it.
- 2026-09-14 First step 2 push to Retell. Found afterward that no phone number was bound in Retell and the Twilio number had no voice routing, so no real call has ever reached the agent; step 1 was verified by evals only. Read-back of deployed config (tools, phone bindings) is now part of a push check, not just the prompt match.
- 2026-09-14 The step 2 prompt does not ask the SMS consent question, even though the rules require consent before the first text and the spoken close promises a summary text. Without an explicit line, Haiku asked the ~60-word consent script at the close in one run of two. Consent belongs with the first text actually sent, the quote at step 3, per the 2026-09-13 decision; the prompt now says so. Accepted: the close promises a text that nothing sends until step 5, which has been true since step 1 and is a build-order artifact, not a product decision. Reconsider at step 3, when the consent case is written.
- 2026-09-14 The closing eval transcript was rewritten from the step 1 flow (address, then callback number) to the step 2 flow (address, photo declined, callback number). Under the step 2 prompt the old transcript read as a skipped photo step and the agent went back for it in one run of two, which the case had not meant to test. The prompt also gained the rule that "that's everything" ends the call even if a step was skipped. Chosen over keeping the old transcript as a "wrap up when asked" test, because a transcript the deployed flow cannot produce grades a situation that never happens.
- 2026-09-14 The "invented" phone number in the photo cases was the shop's own `business.public_phone` from the rules file, which Haiku read back as the caller's number. A plain "never speak a phone number" rule cut it from two failures to one; naming the shop number as not the caller's cut it to zero. Lesson recorded: when the model produces a specific value, grep the prompt for it before calling it a hallucination.
- 2026-09-14 Callback plan is spoken once, at the close, never mid-intake. Added after the routine-tier photo cases twice produced the urgent line ("first thing in the morning") in the middle of the call. Saying it once, from the tier's `callback` line, removes the moment where the wrong tier's wording slipped in.
- 2026-09-14 Retell emailed a deprecation notice for `GET /list-agents` (replacement `POST /v2/list-agents`). Searched the repo: nothing calls it; push.ts only creates, updates, and gets. The flagged call was a one-off curl on 2026-09-12. No change; noted in status so a future check uses v2.
- 2026-09-14 Two string checks were added to the photo cases after the first run passed turns that were wrong: `not-icontains "first thing in the morning"` on the routine-tier cases (the agent said the urgent callback line twice) and a no-digits check on turns where no number belongs (the agent invented "604-555-0199" to confirm the callback number). The rubrics had not asked about either. Accepted: cheap checks are narrow, so they catch these two wordings and not every variant; the prompt fix is what makes the behaviour right. Reconsider if a rubric-based tier check is worth its cost.
- 2026-09-14 A second fixture, `evals/fixtures/p-trap-leak.analysis.json`, is synthetic (hand-written, no photo behind it) so IC-5 is graded against a clear finding as well as the ambiguous real one. Chosen over waiting for a real leaking-trap photo. Reconsider when a real one is texted in: replace, keep the shape.
- 2026-09-14 `get_photo_analysis` takes no arguments. Retell sends a `call` object with `from_number` on every tool call, and the n8n workflow already reads it, so a required `caller_phone` was only a hallucination invitation. push.ts now sends `args_at_root: false`, since `true` flattens the body to the arguments alone and drops the call object (verified in Retell's API reference). Accepted: every tool from now on relies on the wrapper body; if a tool is ever set to args-only, its workflow loses the caller number.
- 2026-09-14 Eval harness for tools (standard promptfoo, verified in the 0.123.0 source): the provider loads its tool list from `evals/tools.js`, which reads `agent/tools.json` at the `build_step` in `agent/settings.json` through the same `toolsForStep()` push.ts uses, so evals and deploy see the same tools. Tool calls that already happened are replayed as Anthropic content blocks (assistant `tool_use`, user `tool_result`) inside `vars.conversation`; promptfoo passes block arrays through untouched. One convenience of our own: a `tool_result` content of `file://fixtures/x.json` is read from that file by `prompt.js`. A tool call in the graded output appears as the block's JSON, so "tool called" and "no tool call" are plain string checks. Chosen over a custom provider or a mock server: nothing to maintain, and cases stay readable YAML. Reconsider at step 4 if multi-tool turns need the loop promptfoo only runs for MCP tools.
- 2026-09-14 `build_step` moved to 2 in `agent/settings.json` when the step 2 cases were written, not when they pass. The evals and the coverage report read it; push.ts also reads it, but push runs the suite first and refuses on a failure, so the tool cannot be deployed with a prompt that fails its cases.

- 2026-09-12 Retell's built-in Claude 4.5 Haiku, billed by Retell, instead of BYOK. Retell support confirms BYOK is unsupported for the built-in LLM; the alternative is a custom LLM websocket server, which is out of scope. CLAUDE.md's "BYOK" line should be updated.
- 2026-09-12 The opener is a literal string in `agent/settings.json` (Retell begin_message), checked at push time for the words "recorded" and "AI assistant", so the disclosures are verbatim and cannot drift with the prompt.
- 2026-09-12 push.ts has no dependencies and runs on Node's built-in TypeScript support; schema validation of the rules file is skipped until js-yaml and ajv are added as devDependencies (asked, not added).
- 2026-09-12 Voice is cartesia-Emily (calm, middle-aged, American) as a starting point; change it in `agent/settings.json`.
- 2026-09-12 Agent temperature is 0.1, set in `agent/settings.json` and mirrored in the eval config. At 0.3 the suite hovered between 94 and 100% run to run; steadier turns matter more than variety on a phone call. Ray confirmed.
- 2026-09-12 Keep the phone price band (photo to quote loop) over the industry fee-only script. Ray confirmed; the fee-first framing in `pricing_policy` makes it defensible.
- 2026-09-12 Rules file v2 is grounded in a survey of Metro Vancouver shops, dispatch scripts, and BC regulators; see `docs/plumbing-research.md`. Values are fictional but shaped like the real thing.
- 2026-09-12 Keep the phone price band even though no real shop quotes one; the agent now leads with the service call fee and calls the band a typical range confirmed on site, which is the honest middle and satisfies BC's estimate rule.
- 2026-09-12 Dry Run is deliberately not a gas contractor. Many Vancouver plumbers are, but it keeps the demo's escalation path single-purpose. Gas smell uses FortisBC's wording and number.
- 2026-09-12 Weekend booked visits run at the regular rate, because the ideal call books a Sunday morning and says so; the v1 rules had Sunday closed, which contradicted the spec.
- 2026-09-12 The agent may state fees (service call, after-hours callout) on request but never a repair number in step 1; the firm-price eval allows the digits 120 only.
- 2026-09-12 Every eval case runs twice at the real temperature (0.3), because the first single-pass run hid three real agent gaps that only showed on a second roll. A flaky turn is a failing turn.
- 2026-09-12 Callback promise is a per-tier `callback` line in the rules file, after the first eval run caught the agent promising the emergency-only 15-minute callback for a routine drip.
- 2026-09-12 Policy values in the rules file are written as plain sentences, not bare tokens (`weekend_surcharge: "None. ..."` rather than `none`), because Haiku read the bare token as "no information".
- 2026-09-12 The eval word budget is a per-case var (`max_words`, default 70) so safety instructions and price refusals can run longer without loosening the limit for ordinary turns.
- 2026-09-12 Evals and the Retell push share one rendering path (`evals/prompt.js` reads `agent/prompt.md` and injects `rules/plumbing.yaml`), so what is graded is what is deployed.
- 2026-09-12 Gas smell is handled as safety-only: instruction to leave and call the gas utility or 911, no intake, no escalation, because a plumber is not the first responder for gas.
- 2026-09-12 The opener is a static Retell begin message, not model-generated, so the recording and AI disclosures are verbatim every time.
- 2026-09-12 Prices in CAD and the fictional shop is in Vancouver, matching the Canadian Twilio number.
- 2026-09-12 Assume a solo shop with one on-call number until decided otherwise. The rules file has a `crew_model` field so the crew version is a config change, not a rewrite.
- 2026-09-12 Rules file is YAML with a JSON Schema alongside it, validated at push time and in evals, so a malformed rules file cannot reach Retell.
